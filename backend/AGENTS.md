# Правила бэкенда

## Структура

Бэкенд является Go-модулем. Исполняемые точки входа размещайте в `cmd/` (сейчас это `cmd/server`), пакеты только для приложения — в `internal/`, а `pkg/` используйте лишь для пакетов, которые допустимо импортировать за пределами модуля. По мере разработки группируйте код мониторинга uptime по функциям.

## Команды

Запускайте эти команды из `backend/`:

```sh
go run ./cmd/server  # Запуск точки входа сервиса
go test ./...        # Запуск тестов всех пакетов
go fmt ./...         # Форматирование Go-кода перед коммитом
```

Не коммитьте скомпилированные бинарные файлы, результаты проверки покрытия и локальные `.env`-файлы.

## Стиль и тестирование

Следуйте идиоматичному Go. Имена пакетов должны быть короткими и в нижнем регистре; экспортируемые идентификаторы используйте в `PascalCase`, неэкспортируемые — в `camelCase`. Имена файлов должны быть описательными и в нижнем регистре, например `config.go` или `health_handler.go`.

Размещайте тесты рядом с исходным кодом, используя суффикс `*_test.go`. Для нескольких сценариев предпочитайте табличные тесты. После изменений запускайте `go test ./...`; добавляйте целевые тесты для нового поведения и исправлений ошибок.
