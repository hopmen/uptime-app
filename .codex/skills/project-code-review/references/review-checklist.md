# Чеклист ревью

Пройди каждую строку; неприменимые пункты отметь с причиной. «Хорошо» — наблюдаемое свидетельство, «Плохо» — сигнал для проверки, а не автоматический дефект. Для каждого замечания докажи связь с diff и ущерб.

## G — всегда

| ID / Проверка | Хорошо | Плохо / что исследовать |
| --- | --- | --- |
| G1. Область и поведение | Известны base/target SHA, изучены новые/удалённые файлы, сценарий до/после и вызывающий код | Проверяется другой checkout; diff обрезан; новые файлы/удалённые проверки потеряны |
| G2. Секреты и данные | Секреты только в локальном env; `.env.example` содержит placeholders; нет token/password/DSN в логах, ответах и public assets | Рабочие ключи, приватные сертификаты, реальные данные в fixtures; секрет в `NEXT_PUBLIC_*`. Не путай фиктивные тестовые значения с утечкой. Для диапазона коммитов проверь промежуточные patch: секрет мог быть добавлен и удалён |
| G3. Границы доверия | Проверка данных и доступа на сервере, безопасные ошибки, параметризация внешних данных | Доверие `userId`, роли, URL, пути или JWT claims от клиента; инъекции, XSS, лишние поля в ответе, stack trace/SQL наружу |
| G4. Достаточность тестов | Тест проверяет наблюдаемое новое поведение: успех, отказ, границу; bugfix воспроизводит регрессию; assertions ловят неправильный результат | Тест повторяет реализацию, моки скрывают нарушенный контракт, удалён полезный тест, основной сценарий/изоляция не проверены. Отделяй пропуск PostgreSQL от unit tests; процент покрытия не заменяет проверку ветвей |
| G5. Имена и мёртвый код | Названия отражают предметную роль и единицы, стиль текущего языка; у изменённых symbols/imports/config есть реальные callers | Неиспользуемый код/пакет, закомментированная реализация, недостижимая ветвь, дублирование, непонятные `data`/`tmp`, seconds vs milliseconds. Перед выводом проверь usages, reflection/framework conventions и codegen |
| G6. Архитектура и зависимости | Ответственность соответствует карте архитектуры; оправданные изменения проведены через все слои; lockfile и manifest согласованы | GORM в HTTP/domain, прямое чтение DB из UI, циклы, дублирование бизнес-логики; новая тяжёлая зависимость ради тривиальной функции. Не требуй несуществующих слоёв |
| G7. Результаты проверок | Выполнены подходящие команды для нужного snapshot, ограничения записаны | Линтер выдан за security-аудит, skip — за pass, старый запуск — за проверку нового diff, failure скрыт после первого шага |

## B — backend/** или влияние на Go API/сервисы

| ID / Проверка | Хорошо | Плохо / что исследовать |
| --- | --- | --- |
| B1. Слои и ошибки | Handler декодирует/авторизует, service валидирует правило, repository сохраняет; context проходит до GORM; ошибки переведены осмысленно | SQL в handler, service импортирует store, потеря context/ошибки, неверный статус, panic на обычном входе, повторная запись ответа |
| B2. Auth и изоляция | Сервер проверяет подпись/алгоритм/срок JWT и пользователя; owner из auth; scoped query; тест двух пользователей | IDOR; отсутствие auth у нового роута; пустой owner; client-supplied owner; принятие неподписанного/просроченного токена; утечка password/token hash |
| B3. Сессии, cookie, CORS | Хеш пароля/refresh; атомарная ротация; корректные Secure/HttpOnly/SameSite/Path и очистка cookie; точный origin при credentials; проверена CSRF-модель cookie-операций | Plaintext secrets, reuse refresh после rotation, гонка сессий; wildcard/отражение origin с credentials; cookie удаляется с другим Path; ослабление production-настроек |
| B4. Вход, файлы, сеть | Лимит тела/файла, проверка MIME и пути, освобождение ресурсов; numeric overflow исключён. Исходящие запросы ограничены timeout/cancellation и проверяют адрес/redirect по модели угроз | Неограниченное чтение, path traversal, доверие extension/filename, временные файлы без cleanup, потеря аватара при неудачном сохранении; SSRF в появившемся HTTP worker, internal/metadata адреса или redirect в них |
| B5. Go корректность и ресурсы | `errors.Is`, сохранённый error context; закрытие DB/files/body; bounded goroutines и жизненный цикл; shared state защищён | Data race, утечка goroutine/timer, блокировка shutdown, игнорирование значимой ошибки, HTTP client без ограничений, путаница time units |
| B6. HTTP/OpenAPI | Реальный route/method/status/DTO соответствует Swagger, auth schemes и generated OpenAPI/ReDoc; старый клиент совместим либо миграция явна | Недокументированный роут; контракт вручную редактирован; пропавшие error/schema/header; устаревшие generated файлы; обязательное новое поле ломает клиента |

## F — frontend/** или изменение потребляемого API/сессии

| ID / Проверка | Хорошо | Плохо / что исследовать |
| --- | --- | --- |
| F1. Next/React границы | App Router conventions актуальны по локальным docs; browser API внутри client boundary; server secrets не попадают в client imports | SSR обращается к window, hooks в Server Component, server module в client bundle; расширение client subtree с измеримым последствием |
| F2. Состояние и эффекты | Полные dependencies, cleanup, pending/error/empty состояния, устаревший async результат не меняет новый экран/сессию | Stale closure, лишний refresh/retry, бесконечный effect, двойной submit, обновление сессии после logout или другого login, optimistic update без rollback |
| F3. API и auth | Поля/методы/единицы совпадают с Go; контролируемые 401/refresh и сетевые ошибки, access token в памяти, multipart без ручного Content-Type | Token в localStorage/URL/log, бесконечные retry, повтор создаёт дубли, слепой `as T` как runtime validation, 204 читается как JSON |
| F4. UI и доступность | Label связан с input; клавиатура/focus работают; ошибка понятна; loading не показывает чужие/старые данные | Click-only div, недоступная форма/диалог, нет ошибки отказа; HTML инъекция через опасный HTML/URL. Доказывай XSS реальным источником и sink |
| F5. Типы, имена, тесты | Strict TS, ясные компоненты/hooks, runtime parsing на значимых границах; Testing Library проверяет пользовательский сценарий | `any`/non-null assertion скрывает nullable ошибку, hook вызван условно, нестабильный key ломает state, snapshot без действий, новый код полностью обходится eslint-disable |

## D — migrations, store, изменение схемы/семантики сохранения

| ID / Проверка | Хорошо | Плохо / что исследовать |
| --- | --- | --- |
| D1. Схема и совместимость | Новые up/down согласованы; порядок/откат/потеря данных описаны; constraints, defaults, indexes, модель и DTO совместимы | Изменена применённая миграция; NOT NULL без backfill; DROP без плана; rollback не работает; неверный numeric range |
| D2. Атомарность и доступ | Связанные операции в транзакции, проверяется RowsAffected, SQL параметризован, запрос scoped владельцем; конкурентные вызовы безопасны | Частичная запись, read-then-write race, неверный cascade, конкатенация пользовательского SQL, full-table update/delete, нестабильная сортировка/неограниченный запрос с показанным риском |
| D3. PostgreSQL проверка | Выполнен интеграционный тест на согласованной тестовой БД, проверены constraints/persistence/rollback | Fake repository выдан за проверку миграции; production DB; `TEST_DATABASE_URL` отсутствует, а тест назван успешным |

## X — сквозные изменения или конфигурация/зависимости

| ID / Проверка | Хорошо | Плохо / что исследовать |
| --- | --- | --- |
| X1. Сквозной контракт | UI → API → service → store проверены сценарием, единицы/поля согласованы; при одностороннем diff проверен потребитель | Фронтенд отправляет другое поле/тип; CORS/cookie ломают отдельный origin; 401/403/empty list трактуются неправильно |
| X2. Сборка и настройки | Версии и lockfiles согласованы; env описан очищенным примером; Go и frontend запускаются независимо | Секрет обязателен при client build, неописанный env, неподдерживаемая Node/Go версия, build output/dependencies в Git; scripts выполняют неожиданные внешние действия |

Для docs/skills/tooling без влияния на приложения B/F/D/X могут быть неприменимы; проверь точность команд, ссылок, безопасность и поведение новых скриптов через G. Статические проверки не доказывают отсутствие уязвимостей или всего мёртвого кода.
