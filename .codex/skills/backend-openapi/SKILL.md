# OpenAPI бэкенда

Поддерживай соответствие между реальным HTTP API, Swaggo-аннотациями и сгенерированной документацией в рамках текущей задачи.

## Источники контракта

Пути ниже указаны от корня репозитория. Прочитай [правила бэкенда](../../../backend/AGENTS.md), раздел Swagger и OpenAPI. Для деталей генерации используй [backend/README.md](../../../backend/README.md).

- Регистрация роутов и обработчики: `backend/internal/server/`; общие сведения и схемы авторизации: `backend/cmd/server/main.go`.
- Именованные DTO, сериализация, валидация и middleware определяют фактические параметры, ответы и доступ к операциям. Проверяй их вместе с обработчиком.
- `backend/cmd/openapi/main.go` использует закреплённый Swaggo, преобразует Swagger 2 в OpenAPI 3.0.3 и валидирует результат. Используй этот генератор вместо отдельного `swag init` или установки последней версии CLI.

## Синхронизация при изменении API

По diff и регистрации маршрутов установи затронутые пары HTTP-метод + полный путь. Учитывай публичные операции и раздачу файлов. При обычном изменении работай с затронутыми операциями; по запросу документировать весь API сверь все существующие API-роуты. Служебные маршруты Swagger UI и выдачи самого контракта не считай предметными операциями API.

- Для нового роута добавь Swaggo-аннотации непосредственно над обработчиком. Для изменённого обнови их по фактическому поведению; при смене пути или метода убери старую операцию. При удалении роута удали соответствующий `@Router` и относящееся к нему описание, сохрани аннотации оставшихся операций общего обработчика.
- Укажи `@Summary`, уникальный `@ID`, `@Tags`, `@Router`, входные параметры через `@Param`, форматы через `@Accept`/`@Produce`, реальные успешные и ошибочные ответы через `@Success`/`@Failure`, значимые заголовки через `@Header`. Для ответа без тела не указывай схему тела. Не добавляй параметры, коды или ограничения, которых нет в реализации.
- Следуй правилам бэкенда для `@Security BearerAuth`, `@Security RefreshCookie`, необязательной cookie и multipart-файлов. Публичным операциям не назначай обязательную авторизацию.
- Синхронизируй именованные DTO и теги полей с сериализацией и реальной валидацией. Учитывай остальные операции, использующие изменённый DTO.
- При новых пакетах обработчиков или DTO обнови области сканирования `cmd/openapi`. Проверь преобразования генератора, которые обращаются к конкретным путям и схемам: изменение или удаление такого роута требует изменения соответствующего преобразования.
- Обнови проверки затронутых операций в `backend/internal/server/swagger_test.go`. При удалении или переносе проверь отсутствие старой пары метод + путь в контракте, а при добавлении — наличие новой. Успешная генерация сама по себе не доказывает полноту описания роутов.

## Генерация и проверка

После обновления аннотаций выполни из корня репозитория:

```sh
node .codex/skills/backend-openapi/scripts/sync-docs.mjs
```

[Скрипт синхронизации](scripts/sync-docs.mjs) запускает `go generate ./docs`, сохраняет снимки JSON/YAML и повторяет генерацию. Если результаты совпадают, сразу генерирует ReDoc через существующий `backend/scripts/generate-redoc.mjs`. Скрипт определяет `backend/` по своему расположению и работает из любого текущего каталога; проверка повторяемости не зависит от незакоммиченного diff.

Нужны Go, Node.js 22.12+ и npm 10+; проектный скрипт ReDoc использует закреплённый Redocly CLI, при первом запуске npm скачивает его. При ошибке любой команды или несовпадении JSON/YAML скрипт завершается с ненулевым кодом и не запускает следующие шаги. Сообщи причину и какие артефакты остались не обновлены; не выдавай частичную генерацию за завершённую синхронизацию.

Затем выполни из `backend/`:

```sh
go fmt ./...
go test ./...
```

Проверь diff `backend/docs/openapi.json`, `backend/docs/openapi.yaml` и `backend/docs/redoc.html`: затронутые операции, схемы и авторизация должны соответствовать коду, удалённые операции должны исчезнуть. Не редактируй сгенерированные файлы вручную. Проверку соответствия аннотаций поведению обработчиков выполняй по коду: скрипт автоматизирует генерацию, а не проверку полноты API.

При изменении скрипта запусти его поведенческие проверки: `node --test .codex/skills/backend-openapi/scripts/sync-docs.test.mjs`.

Включай сгенерированные JSON, YAML и ReDoc HTML в изменение вместе с исходниками контракта. В итоговом ответе кратко укажи обновлённые операции и реально выполненные проверки. Публикация и коммиты регулируются правилами репозитория, а не самим навыком.
