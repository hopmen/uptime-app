# Ветки и коммиты

Применяйте эти правила перед началом каждой задачи и при создании коммитов.

## GitHub Flow и ветки

- Перед началом каждой задачи создавайте отдельную ветку от актуальной `main`.
- Именуйте ветки в формате `feat/<nazvanie-zadachi>` для новой функциональности и прочих изменений или `fix/<nazvanie-zadachi>` для исправления ошибок.
- Название задачи пишите транслитом, строчными латинскими буквами; слова разделяйте дефисами. Примеры: `feat/istoriya-proverok`, `fix/oshibka-avtorizatsii`.
- Все изменения по задаче выполняйте в её ветке; не коммитьте напрямую в `main`.

## Подготовка коммита

- Зафиксируйте только относящиеся к задаче изменения. Не включайте чужие или ранее подготовленные изменения пользователя без его указания; проверяйте индекс перед коммитом.
- Не коммитьте сгенерированные зависимости, результаты сборки, локальные бинарные файлы и учётные данные. Храните секреты в неотслеживаемых `.env`-файлах.

## Оформление коммитов

- Формат: Conventional Commits (feat, fix, refactor, test, docs, chore)
- Заголовок до 72 символов, в повелительном наклонении
- Без эмодзи, без «significantly improved» и прочей воды
- Тело — только если нужно объяснить «почему», а не «что»
- Один логический шаг — один коммит
- Пишите заголовки и тела коммитов на русском языке, сохраняя английский тип Conventional Commits.

После завершения задачи и проверок следуйте [правилам Pull Request](pull-requests.md).
