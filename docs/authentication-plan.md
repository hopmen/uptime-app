# Авторизация с PostgreSQL в Docker

## Summary

Для работы с PostgreSQL используется **GORM v2** с драйвером `gorm.io/driver/postgres`. Для небольшой модели пользователей и сессий он даёт типизированные модели, транзакции и подключение к PostgreSQL поверх `pgx`. Схема при этом остаётся под контролем версионированных SQL-миграций, без `AutoMigrate` при старте сервиса.

## Key Changes

- Добавить GORM и PostgreSQL-драйвер; создать модели `User` и `RefreshSession` и репозитории на GORM.
- Добавить `backend/compose.yaml`:
  - сервис `postgres` с PostgreSQL, именованным volume, healthcheck и опубликованным портом;
  - одноразовый сервис `migrate`, зависящий от готовности PostgreSQL и применяющий SQL-миграции;
  - все пароли и connection string читаются из неотслеживаемого `.env`; в репозиторий добавить `.env.example`.
- Хранить миграции в отдельных versioned `up/down` SQL-файлах; GORM `AutoMigrate` не использовать. Это исключает неявные изменения схемы и сохраняет контролируемый rollback.
- Схема:
  - `users`: UUID, уникальный нормализованный email, bcrypt-хеш пароля, `created_at`, `updated_at`;
  - `refresh_sessions`: UUID, `user_id` с внешним ключом, уникальный SHA-256-хеш refresh-токена, `expires_at`, `created_at`; индекс для поиска токена и очистки истёкших сессий.
- Реализовать API `/api/v1/auth`:
  - `POST /register` и `POST /login` принимают `{email,password}`, возвращают `{user,accessToken,expiresIn}` и устанавливают refresh cookie;
  - `POST /refresh` читает cookie, атомарно ротирует refresh-сессию и возвращает новый access JWT.
- Access JWT: HS256, `sub`, `email`, `iat`, `exp`, `jti`, срок 15 минут. Refresh-токен — криптографически случайный opaque токен в `HttpOnly` cookie, срок 30 дней.
- Настроить CORS для единственного `FRONTEND_ORIGIN` с credentials; параметры `Secure` и `SameSite` cookie вынести в конфигурацию окружения.

- Unit-тесты валидации email/пароля, bcrypt, JWT claims и генерации refresh-токена.
- Интеграционные тесты GORM-репозиториев с PostgreSQL: уникальность email, транзакционная ротация, истёкший и повторно использованный refresh-токены.
- HTTP-тесты регистрации, входа, refresh, cookie-атрибутов и ошибок `400`/`401`/`409`.
- Проверка локального сценария: `docker compose up -d postgres`, применение миграций, затем `go test ./...`.

## Assumptions

- Docker запускает PostgreSQL и миграции; Go API запускается отдельно через `go run ./cmd/server`.
- Регистрация сразу авторизует пользователя.
- Logout, `/me`, отзыв всех сессий и восстановление пароля остаются вне первого релиза.
