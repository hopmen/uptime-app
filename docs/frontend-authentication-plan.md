# Авторизация на фронтенде

## Контракт

- Браузер обращается к `NEXT_PUBLIC_API_URL` напрямую и передаёт cookie через `credentials: "include"`.
- Backend endpoints: `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `POST /api/v1/auth/refresh`.
- Access JWT хранится только в памяти React. Refresh-токен хранит backend в `HttpOnly` cookie.
- В первый релиз не входит logout: для корректного выхода нужен backend endpoint отзыва refresh-сессии.

## Принятые решения

- В первом релизе используются отдельные маршруты `/login`, `/register` и `/dashboard`.
- Для отображения пользователя после refresh email извлекается из JWT payload; backend не расширяется endpoint-ом `/me`.
- Защита `/dashboard` клиентская: страница не содержит чувствительных server-rendered данных.
